# 求职助手 · 产品方案 v1

> 定位：帮 **有履历、在跨赛道/跨岗位迁移的 ToB 产品人** 过真实招聘三关的助手  
> 模拟决策者：**人事筛简历 → 业务面深度 → HR 谈薪**  
> 首发人群：**3–10 年经验**的社招求职者；垂类优先 **车联网 / 网络安全 / 合规（含信息安全→数据安全迁移）**  
> 明确不做：应届生、纯小白、零基础转行（不适合本 MVP）

---

## 1. 问题与目标

### 1.1 真实痛点（来自首要用户典型经历）

| 关卡 | 痛点 | 失败/卡点形态 |
|------|------|----------------|
| 人事 | 简历主线不清、缺量化、与 JD 不对齐；跨赛道时「像不像这个岗」说不清 | 电话不错但不约面；简历保护期卡住多岗投递 |
| 业务 | 经历会背，但取舍/计划拆解/冲突处理讲不透；相邻岗位（如信息安全→数据合规）迁移叙事弱 | 「讲述表层化」「偏既定计划执行」；一面过二面挂 |
| 谈薪 | 不懂结构、被流水压价、不知哪些点可谈；主机厂/大厂 offer 拆分复杂 | 总包预期与 offer 结构错位；应收 vs 实发说不清 |

### 1.2 产品目标

- **不是**面向所有求职者的泛 AI 改简历 / 陪聊  
- **而是**针对「已有 ToB 交付履历、正在换公司或换相邻岗位」的人，按招聘角色给出可执行反馈：过不过、差在哪、下一句怎么说  

### 1.3 成功标准（MVP）

首要用户完成一次针对真实 JD 的闭环后，能带走：

1. 一份「人事视角」打分报告 + 可落地的改写清单  
2. 一轮「业务视角」模拟面记录 + 表层化诊断  
3. 一份谈薪对照表 + 避坑问题 / 话术草稿

## 2. 目标用户（必须说清：服务谁、不服务谁）

### 2.1 一句话 ICP（理想客户）

**3–10 年经验、做过 ToB 平台/安全/运维类产品、正在投主机厂或安全相关合规/产品岗，且履历需要「按 JD 重讲故事」而不是从零找工作的人。**

首发只做这类**有履历的社招迁移**；不做应届生、不做纯小白。

### 2.2 首要用户画像（Primary）

| 维度 | 定义 |
|------|------|
| 身份 | 产品经理为主；也包含「产品+项目」双角色、或从安全工具/平台侧转主机厂合规岗的人 |
| 经验 | **3–10 年**；至少有一段可被业务深挖的完整项目/客户交付（不是校招、不是纯小白） |
| 背景赛道 | 云原生 / 安全运营 / 运维安全 / 车联网 CSMS·TARA·VSOC 等，至少一段可讲清的平台或合规落地 |
| 当前求职动作 | 在职或刚离职的**主动社招**；已有完整简历，频繁按不同 JD 改主线、模拟面试、谈薪 |
| 目标去向 | 主机厂、车企软件侧、安全厂商、合规相关岗位；常见迁移包括：信息安全合规 → 数据合规、工具型产品 → 更贴整车/业务的合规或系统岗 |
| 能力特征 | 有真实项目与客户（如主机厂落地），但不擅长：把经历写成人事爱看的主线、把案例讲到业务认可的深度、把 offer 结构谈清楚 |
| 核心动机 | 不是「教我入门当产品」，而是「帮我过这一关、拿到这个岗」 |
| 付费/使用触发 | 约面前后 48 小时、改简历卡壳、二面挂掉复盘、HR 约谈薪当周 |

**典型一天（场景锚点）**

> 手里有 1–2 个在推进的 JD（例如数据合规、网络安全系统/产品）。早上按 JD 改简历主线；下午业务面，担心又被问到「计划怎么拆」「冲突怎么推」时讲浅；晚上或次日 HR 发来拆分，要在流水、年终是否保底、公积金上做选择。

### 2.3 为什么是这群人（针对性，而非泛产品经理）

1. **迁移叙事难**：履历跨云、安全、车联网，人事看「杂」，业务看「够不够深」——通用改简历工具解决不了「对这个 JD 该强调哪条线」。  
2. **过关标准特殊**：业务面常考法规拆解、阀点/里程碑、跨部门冲突、供应商/系统对接取舍；需要 STAR + 反表层化，而不是互联网 C 端产品那套「增长/用户故事」话术。  
3. **谈薪结构复杂**：主机厂/大厂常见基本+岗位+绩效+年终系数+公积金口径；「流水压价 vs 应收总包」是高频痛点。  
4. **我们有可验证的黄金用例**：产品规则与 prompt 可先用这一垂类的真实失败/成功路径打磨，再扩邻域。

### 2.4 应届生 / 纯小白：不做进 MVP

决策已定：**MVP 只面对 3–10 年有履历的社招求职者**；应届生、纯小白、零基础转行不适合本切口（缺可深挖交付，三关会退化成模板与八股，也与创始人可验证路径不一致）。校招若未来要做，另立项，不挤进当前默认任务流。

### 2.5 明确不服务（首发 Out of scope）

| 非目标用户（首发） | 原因 |
|--------------------|------|
| 应届生、纯小白、零基础转行 | 见 2.4；MVP 明确不做 |
| 经验不足 3 年且几乎无可深挖项目 | 业务关「反表层化」缺少原料 |
| 纯技术岗求职（开发/测试刷题为主） | 过关逻辑是题库与编码，不是三关叙事 |
| 纯职能 HR/行政/销售话术训练 | 面试模型不同 |
| 想「一键海投 / 自动改到能骗过 ATS」的用户 | 与「不编造经历、可验证深度」原则冲突 |

### 2.6 次要用户（可服务，但不为他们定 MVP）

- 同一垂类里偏 **售前 / 解决方案**，需要按 JD 调简历与案例深度的人  
- 安全厂商 PM，主线更稳、主要需要谈薪与压力面（人事关权重可降低）  
- 二期同框架扩展：通用 ToB 平台 PM、其他强合规行业（须另做行业题库）  

### 2.7 用户分层与产品对应

| 层级 | 是谁 | 产品必须提供的 |
|------|------|----------------|
| P0 首要 | **3–10 年**、车联网/网安/合规方向、跨岗或跨雇主迁移中的产品人 | JD 定制主线、业务反表层化追问、复杂薪酬结构对照 |
| P1 扩展 | 同垂类售前/方案、安全厂商 PM | 复用三关框架，题库与关键词包可配置 |
| P2 远期 | 更广 ToB 社招 PM（仍建议 3 年+有履历） | 抽「迁移求职」共性，减弱垂类绑死文案 |
| 不做 | 应届 / 纯小白 | 不在本产品 MVP 范围 |

### 2.8 核心场景（一条主路径）

```
上传简历 + 粘贴 JD（明确目标岗：如数据合规 / CSMS 产品）
    → 人事评分与「按该 JD 的主线」改写建议
    → 进入业务模拟（追问迁移边界、计划拆解、冲突取舍）
    → 按 STAR + 反表层化诊断回答深度
    → 拿到 offer 结构后进入谈薪辅助（流水 vs 应收、年终口径）
```

次要场景（后期）：多 JD 主线对比、挂面复盘、个人 STAR 案例库沉淀。

## 5. 三关能力设计

### 5.1 人事关：简历评分与改写

**输入**

- 简历全文（结构化优先：工作经历 / 项目 / 优势）  
- 目标 JD  
- 可选：求职意向主线（如「车联网合规产品」）

**输出**

| 维度 | 说明 |
|------|------|
| 匹配度 | 与 JD 关键词 / 职责的覆盖 |
| 主线清晰度 | 是否像一条可讲的职业故事 |
| 可信度 | 量化、客户/场景、职责边界是否清楚 |
| 风险项 | 时间断层、过短经历、术语硬伤、夸大风险 |
| 改写建议 | 按段落：保留 / 压缩 / 重写 / 补量化 |

**评分原则（产品约束）**

- 必须给出**扣分理由**，禁止只给分数  
- 建议按「人事会怎么刷」写，不用业务黑话堆砌  
- 改写默认**不编造经历**；缺信息标「待用户补充」

### 5.2 业务关：面试模拟

**输入**

- 简历 + JD（继承任务）  
- 可选：用户指定要练的案例（如 SRM、法规库解耦）

**流程**

1. 1 分钟自我介绍（含匹配点）  
2. 深挖 1–2 个项目（追问链）  
3. 情景题 / 压力题（计划拆解、冲突、短板）  
4. 反问环节提示（用户问面试官什么）

**诊断维度（针对「表层化」）**

| 维度 | 表层表现 | 合格表现 |
|------|----------|----------|
| STAR 完整度 | 只有背景和职责 | Action/Result 具体 |
| 决策与取舍 | 只说「后来做成了」 | 选项、标准、谁拍板 |
| 个人贡献 | 「我们」过多 | 清楚「我做了什么」 |
| 复盘 | 无 | 若重来会怎么做 |
| JD 迁移 | 硬套旧经验 | 说清可迁移方法与边界 |

**输出**

- 本轮深度分 + 最弱 1–2 点  
- 针对最弱题的「补强口述稿」（60–90 秒）  
- 可收藏为案例库条目

### 5.3 谈薪关：与 HR 沟通辅助

**输入**

- 当前：月薪结构、年终、奖金、公积金基数、补贴  
- Offer：基本/岗位/绩效、年终口径、试用期、调薪、其他  
- 用户底线与目标年包  

**输出**

- 双方**真实年包区间**（保守 / 目标 / 乐观）  
- 结构风险点（基本过低、年终不保、流水压价等）  
- 优先谈的 3 个点 + 可放弃的点  
- 话术：说明「应收结构 vs 流水」、要证据时怎么递  

**原则**

- 不算「保证你谈到 X」；给**决策信息 + 表达模板**  
- 明确标注：年终/绩效系数未书面确认时，按区间展示，不按满额单点展示

## 7. 关键用户流程

### 流程 A：准备投递

1. 新建任务 → 上传简历 + 粘贴 JD  
2. 跑人事关 → 看分与红灯 → 按建议改简历（站内或导出）  
3. 认为过关后，标记「可投递」

### 流程 B：约面后刷题

1. 进入同一任务的业务关  
2. 选「完整模拟」或「只练薄弱点」  
3. 结束后看诊断，把补强稿练到能口述  

### 流程 C：拿到口头/书面 offer

1. 填结构字段  
2. 看总包对照与风险  
3. 复制话术去聊；回来可更新「对方答复」再迭代策略

## 8. 技术选型

结合已有栈（Vue3 + Go + SQLite）与已拍板约束：

| 层 | 选型 | 理由 |
|----|------|------|
| 前端 | Vue 3 + Vite | 熟悉；工作台 SPA |
| 后端 | Go | 熟悉；上传与 API 清晰 |
| 存储 | JSON 文件（`data/tasks.json`） | M1 零 CGO、依赖少、易备份；后续可换 SQLite |
| 部署 | **可公网/局域网访问的 Web 服务**（非纯本机桌面工具） | 方便真实投递场景随时用；可用单机 Docker / 一台云主机 |
| AI | OpenAI 兼容协议，**服务端对接自有中转站** | Key 与 Base URL 仅服务端配置，不暴露给终端用户 |
| 文档解析 | **Markdown / 纯文本 / docx / PDF** 均需支持 | MVP 输入门槛对齐真实投递材料 |

### 模块划分

```
apps/web          # Vue3 工作台（浏览器访问）
apps/api          # Go HTTP API
  /tasks
  /hr/analyze
  /interview/sessions
  /salary/analyze
internal/llm      # 中转站 client + 三角色 prompt
internal/resume   # md / txt / docx / pdf 解析与结构化
```

### AI 调用原则

- 人事 / 业务 / 谈薪使用**不同 system prompt 与输出 schema**（三角色隔离）  
- 业务模拟要带「反表层化」评分细则  
- 中转站：`base_url` + `api_key` + `model` 写在服务端环境变量 / 配置文件，**首发不提供「用户自填 Key」入口**（二期可加）  
- 用户简历与 JD 存于自建服务；产品需有隐私说明  

### 简历解析原则

| 格式 | MVP 要求 |
|------|----------|
| Markdown / 纯文本 | 直接入库与结构化 |
| docx | 抽正文与基本标题层级，再结构化 |
| PDF | 抽文本（优先可选中文本型 PDF；扫描件 OCR 标为降级/二期增强） |

解析失败时明确报错并允许用户改贴纯文本，不静默空跑。

## 9. MVP 范围与非目标

### MVP 做（主线三关必须跑通）

首发原则：**人事 → 业务 → 谈薪整条故事一次打通**。只做单关会沦为「又一个改简历/陪聊」，相对 Boss 直聘等平台没有完整过关叙事，故不做「先只上人事关演示」。

- 可访问的 Web 服务（浏览器打开即用）  
- 任务创建：上传 **md / txt / docx / pdf** + 粘贴 JD  
- ① 人事关：评分报告 + 改写建议（可选生成改写稿）  
- ② 业务关：模拟对话（介绍 + 3–5 追问 + 总结诊断，含反表层化）  
- ③ 谈薪关：结构表单 + 年包对照 + 避坑问题 / 话术  
- 服务端对接自有 LLM 中转站  
- SQLite 持久化  

### MVP 不做

- 自动投递 / 爬岗位 / 替代 Boss 直聘的岗位流量  
- 多租户 SaaS 计费、用户自助注册体系（首发可以是受控访问：账号白名单或简单登录）  
- 终端用户自填模型 Key（首发仅运营方中转站）  
- 真人面试官撮合  
- 扫描件 PDF 的高精 OCR（文本型 PDF 必须支持）  
- 英文面试专线（可作二期开关）

## 10. 里程碑

| 阶段 | 交付 | 验收 |
|------|------|------|
| M0 方案 | 本文档对齐 | 人群 + 四项决策确认 |
| M1 骨架 | Vue + Go；可部署 Web；任务 CRUD；四格式上传解析 | 浏览器访问；简历 md/docx/pdf/txt 能进任务 |
| M2 人事关 | 中转站接入 + 分析 API + 报告页 | 真实简历+JD → 分项分与改写清单 |
| M3 业务关 | 模拟会话 + 反表层化诊断 | 能打出「表层化」类反馈与补强稿 |
| M4 谈薪关 | 结构计算 + 话术 | 流水/结构对照 + 避坑问题 |
| M5 主线验收 | 三关串联打磨 + 部署文档 | **用自己的一条真实求职任务从头跑通三关** |

M2–M4 可并行开发界面，但 **M5 以「整条主线可演示」为发布门槛**，不以单关上线为完成。

## 11. 已拍板决策

| # | 问题 | 决策 |
|---|------|------|
| 1 | 部署形态 | **可访问的 Web 服务**（非纯本机单用户工具） |
