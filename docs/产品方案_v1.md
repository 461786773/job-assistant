# 求职助手 · 产品方案 v1

> 定位：**职场心理教练**——陪伴有履历的职场人（尤其跨赛道/跨岗位迁移的 ToB 产品人）在求职、晋升、沟通等高压节点里，稳住状态、理清选择、练好表达  
> 教练怎么帮：用**觉察与跟踪**稳住心理，用**场景辅导**理清情绪与下一步，用**过关工具**（人事筛简历 → 业务面深度 → HR 谈薪）把「下一句怎么说」练到可执行  
> 首发人群：**3–10 年经验**的社招 / 在职迁移者；垂类优先 **车联网 / 网络安全 / 合规（含信息安全→数据安全迁移）**  
> 明确不做：应届生、纯小白、零基础转行；**不是临床心理诊疗 / 危机干预替代品**；也不是又一个泛 AI 改简历工具

---

## 0. 核心策略（专项调整）

### 0.1 策略一句话

产品首先是**职场心理教练**，不是「招聘三关工具箱再挂个心理彩蛋」。用户来找的是：有人帮我在关键节点稳住、想清、说得出；简历/面试/谈薪是教练场景下的**训练与过关手段**。

### 0.2 教练模型（主从关系）

| 层 | 角色 | 解决什么 | 典型产出 |
|----|------|----------|----------|
| **教练主线** | 职场心理教练 | 求职 / 晋升 / 沟通中的压力、自我怀疑、冲突耗竭；帮用户拆开事实与评判，选定下一步 | 辅导对话、行动卡、「下一句怎么说」 |
| **状态层** | 心理健康跟踪 | 把零散情绪变成可回看曲线，与关键事件挂钩，供教练会话引用 | 打卡、趋势、周复盘摘要 |
| **过关工具层** | 三关训练 | 简历 / 面试 / 谈薪「过不过、差在哪、怎么改/怎么答」 | 报告、模拟记录、谈薪对照与话术 |

关系：**教练主线统领** → 跟踪提供上下文 → 三关工具在需要时被教练调用或由用户主动进入，而不是反过来用工具定义产品。

### 0.3 原则与边界

- **教练身份优先**：默认入口与叙事是「链接进入 → 评测与诉求 → 疏导/预约 → 按需分支服务」，不是「先建一个投递任务」。  
- **职场向、非诊疗**：AI 评估与疏导支持觉察、表达整理、压力缓冲与行动建议；**不诊断、不开药**。真人私人辅导预约是**转介/预约通道**，不替代医疗机构。  
- **高风险兜底**：出现自伤/伤人等危机信号时，明确提示寻求专业/紧急帮助，产品不继续「陪聊式处理危机」。  
- **绑在真实节点上**：辅导与跟踪挂在求职、晋升、沟通等具体诉求上，避免泛泛心灵鸡汤。  
- **隐私优先**：心理健康数据默认仅本人可见；存储与导出需单独说明。  

### 0.4 主故事线（用户使用路径）

这是产品的**主故事线**；求职三关、晋升/沟通服务都是故事线中的分支，不是并列首页。

```
1. 链接登录
       ↓
2. 第一次心理评测（问卷）→ AI 评估 + 分析报告
       ↓
3. 询问具体诉求（求职 / 晋升 / 沟通 / 先疏导 / 暂不确定）
       与第 2 步结果结合，生成建议路径
       ↓
4. 用户可随时回看自己的评估结果与 AI 分析
       ↓
5. AI 心理疏导（教练对话）
       + 支持预约私人心理辅导（真人）
       ↓
6a. 诉求=找工作 → 子流程：人事 → 业务 → 谈薪
6b. 诉求=晋升 / 沟通 → 对应场景服务（述职/向上/冲突等）
       ↓
8. 持续跟踪心理健康
       每次进入疏导或关键节点前：完成问卷调查（三分钟自评等）
       → 写入跟踪曲线，供下次评估与疏导引用
```

| 步骤 | 用户做什么 | 系统做什么 |
|------|------------|------------|
| 1 链接登录 | 打开邀请/访问链接进入应用 | 鉴权建会话（受控访问；细则可迭代） |
| 2 初次评测 | 完成初次心理评估问卷 | AI 出具评估摘要与分析（非诊断） |
| 3 明确诉求 | 确认或补充具体诉求 | 结合评测结果推荐主路径与下一步 |
| 4 回看结果 | 打开「我的评估」 | 展示历史问卷、AI 分析、趋势对照 |
| 5 疏导与预约 | AI 对话疏导；可选约私人辅导 | 教练会话；预约表单/对接通道 |
| 6 求职子流程 | 需要找工作时进入 | 人事 → 业务 → 谈薪 |
| 7 晋升/沟通 | 选择对应诉求 | 场景化教练 +（后续）专用训练能力 |
| 8 跟踪 | 每次按要求填问卷 | 记录、趋势、与疏导上下文联动 |

问卷资产：[`初次心理评估问卷.md`](./初次心理评估问卷.md)（步骤 2）、[`三分钟自评表.md`](./三分钟自评表.md)（步骤 8 等高频入口）。

## 1. 问题与目标

### 1.1 真实痛点（来自首要用户典型经历）

| 关卡 / 场景 | 痛点 | 失败/卡点形态 |
|------|------|----------------|
| 人事 | 简历主线不清、缺量化、与 JD 不对齐；跨赛道时「像不像这个岗」说不清 | 电话不错但不约面；简历保护期卡住多岗投递 |
| 业务 | 经历会背，但取舍/计划拆解/冲突处理讲不透；相邻岗位（如信息安全→数据合规）迁移叙事弱 | 「讲述表层化」「偏既定计划执行」；一面过二面挂 |
| 谈薪 | 不懂结构、被流水压价、不知哪些点可谈；主机厂/大厂 offer 拆分复杂 | 总包预期与 offer 结构错位；应收 vs 实发说不清 |
| 求职心理 | 长期投递耗竭、挂面后自我否定、在职偷投的焦虑与羞耻感 | 能力其实够，但状态崩导致发挥失常或直接放弃 |
| 晋升心理 | 述职前 rumination、怕暴露短板、与上级预期错位带来的持续紧张 | 「会干活不会呈现」；晋升窗口错过或谈崩 |
| 沟通心理 | 跨部门冲突、向上管理、被否定后情绪劫持 | 会后反复内耗；该争取的没争取、该止损的没止损 |

### 1.2 产品目标

- **不是**泛 AI 改简历 / 泛陪聊，也**不是**通用心理健康 App 或临床咨询替代  
- **而是**一个**职场心理教练**：在求职、晋升、沟通等节点上，帮用户稳住状态、理清选择、练好表达  
- 三关（人事 / 业务 / 谈薪）是教练场景下的**过关训练工具**，服务于「这个节点我怎么过」，而不是产品的唯一身份  

### 1.3 成功标准（MVP）

首要用户按主故事线走通后，能带走：

1. 一次**链接登录 → 初次评测 → AI 评估分析**的完整首访体验  
2. 明确的**诉求选择**（与评测结合的推荐路径）  
3. 可回看的**评估结果页**  
4. 至少一次 **AI 心理疏导**；并看到**私人心理辅导预约**入口  
5. 持续跟踪：关键进入前完成问卷，能看见状态变化  

若诉求为找工作，额外带走：

6. 人事报告 + 业务模拟诊断 + 谈薪对照（子流程可跑通）  

若诉求为晋升 / 沟通，额外带走：

7. 对应场景的教练服务与可执行下一步

## 2. 目标用户（必须说清：服务谁、不服务谁）

### 2.1 一句话 ICP（理想客户）

**3–10 年经验、做过 ToB 平台/安全/运维类产品、正在换东家或争取晋升，既需要人帮他把状态稳住、把选择理清，也需要在关键节点把简历/面试/谈薪练到位的人。**

首发只做这类**有履历的社招 / 在职迁移与晋升**；不做应届生、不做纯小白；产品身份是**职场心理教练**（非临床诊疗）。

### 2.2 首要用户画像（Primary）

| 维度 | 定义 |
|------|------|
| 身份 | 产品经理为主；也包含「产品+项目」双角色、或从安全工具/平台侧转主机厂合规岗的人 |
| 经验 | **3–10 年**；至少有一段可被业务深挖的完整项目/客户交付（不是校招、不是纯小白） |
| 背景赛道 | 云原生 / 安全运营 / 运维安全 / 车联网 CSMS·TARA·VSOC 等，至少一段可讲清的平台或合规落地 |
| 当前求职动作 | 在职或刚离职的**主动社招**；已有完整简历，频繁按不同 JD 改主线、模拟面试、谈薪；或在职准备**晋升述职** |
| 目标去向 | 主机厂、车企软件侧、安全厂商、合规相关岗位；常见迁移包括：信息安全合规 → 数据合规、工具型产品 → 更贴整车/业务的合规或系统岗 |
| 能力特征 | 有真实项目与客户（如主机厂落地），但不擅长：把经历写成人事爱看的主线、把案例讲到业务认可的深度、把 offer 结构谈清楚；高压节点易自我否定或沟通耗竭 |
| 核心动机 | 不是「再找一个改简历网站」，而是「有个职场教练陪我过这个节点——状态别崩、话能说清、关能过」 |
| 付费/使用触发 | 约面前后 48 小时、改简历卡壳、二面挂掉复盘、HR 约谈薪当周；晋升述职前一周；重大冲突会后当晚；连续高压想有人帮看着状态 |

**典型一天（场景锚点）**

> 面完情绪低落，先打开教练：把「自我否定」和「可改进点」拆开，定一个今晚能做的动作。若还要推 JD，再进人事关改主线；若明天有业务面，用模拟把「计划怎么拆」练深。状态打卡把压力峰值标在「二面 / 晋升沟通 / 冲突会」等事件上，方便下周回看触发点。

### 2.3 为什么是这群人（针对性，而非泛产品经理）

1. **迁移叙事难**：履历跨云、安全、车联网，人事看「杂」，业务看「够不够深」——通用改简历工具解决不了「对这个 JD 该强调哪条线」。  
2. **过关标准特殊**：业务面常考法规拆解、阀点/里程碑、跨部门冲突、供应商/系统对接取舍；需要 STAR + 反表层化，而不是互联网 C 端产品那套「增长/用户故事」话术。  
3. **谈薪结构复杂**：主机厂/大厂常见基本+岗位+绩效+年终系数+公积金口径；「流水压价 vs 应收总包」是高频痛点。  
4. **高压长周期**：社招迁移 / 晋升往往持续数周到数月，能力问题与心理耗竭缠在一起——只做技能辅导不够，只做泛泛倾诉也不够。  
5. **我们有可验证的黄金用例**：产品规则与 prompt 可先用这一垂类的真实失败/成功路径打磨，再扩邻域。

### 2.4 应届生 / 纯小白：不做进 MVP

决策已定：**MVP 只面对 3–10 年有履历的社招求职者**；应届生、纯小白、零基础转行不适合本切口（缺可深挖交付，三关会退化成模板与八股，也与创始人可验证路径不一致）。校招若未来要做，另立项，不挤进当前默认任务流。

### 2.5 明确不服务（首发 Out of scope）

| 非目标用户（首发） | 原因 |
|--------------------|------|
| 应届生、纯小白、零基础转行 | 见 2.4；MVP 明确不做 |
| 经验不足 3 年且几乎无可深挖项目 | 业务关「反表层化」缺少原料 |
| 纯技术岗求职（开发/测试刷题为主） | 过关逻辑是题库与编码，不是三关叙事 |
| 纯职能 HR/行政/销售话术训练 | 面试模型不同 |
| 想「一键海投 / 自动改到能骗过 ATS」的用户 | 与「不编造经历、可验证深度」原则冲突 |
| 需要临床心理治疗 / 精神疾病诊疗的用户 | 产品边界是职场支持，须引导专业服务 |
| 把产品当 24h 危机热线的用户 | 危机场景仅做识别与转介提示，不做持续危机陪护 |

### 2.6 次要用户（可服务，但不为他们定 MVP）

- 同一垂类里偏 **售前 / 解决方案**，需要按 JD 调简历与案例深度的人  
- 安全厂商 PM，主线更稳、主要需要谈薪与压力面（人事关权重可降低）  
- 二期同框架扩展：通用 ToB 平台 PM、其他强合规行业（须另做行业题库）  

### 2.7 用户分层与产品对应

| 层级 | 是谁 | 产品必须提供的 |
|------|------|----------------|
| P0 首要 | **3–10 年**、车联网/网安/合规方向、跨岗或跨雇主迁移中的产品人 | **职场心理教练**主路径（求职/晋升/沟通）+ 轻量跟踪；需要时调用 JD 主线改写、反表层化模拟、薪酬对照 |
| P1 扩展 | 同垂类售前/方案、安全厂商 PM；在职晋升述职者 | 同一教练框架；晋升/沟通权重更高；题库与关键词包可配置 |
| P2 远期 | 更广 ToB 社招 PM（仍建议 3 年+有履历） | 抽「职场高压节点教练」共性，减弱垂类绑死文案 |
| 不做 | 应届 / 纯小白；临床诊疗需求 | 不在本产品 MVP 范围 |

### 2.8 核心场景

主故事线见 **§0.4**。以下为分支展开。

**分支：求职过关（步骤 6）**

```
上传简历 + 粘贴 JD
    → 人事评分与改写建议
    → 业务模拟 + 反表层化诊断
    → 谈薪结构对照与话术
    → 关键节点回到疏导 / 问卷跟踪
```

**分支：晋升 / 沟通（步骤 7）**

```
基于评测 + 诉求进入场景服务
    → 教练疏导（述职压力 / 冲突 / 向上表达等）
    → 可执行动作与「下一句怎么说」
    → （后续可增强）述职稿、沟通演练等专用能力
    → 问卷跟踪回写状态
```

次要场景（后期）：多 JD 主线对比、挂面复盘、STAR 案例库、私人辅导预约履约回访。

## 5. 能力设计

> 结构：**5.4 职场心理教练**与 **5.5 心理健康跟踪**是产品主身份与状态层；**5.1–5.3 三关**是教练场景下可调用的过关训练工具。

### 5.1 人事关：简历评分与改写（过关工具）

**输入**

- 简历全文（结构化优先：工作经历 / 项目 / 优势）  
- 目标 JD  
- 可选：求职意向主线（如「车联网合规产品」）

**输出**

| 维度 | 说明 |
|------|------|
| 匹配度 | 与 JD 关键词 / 职责的覆盖 |
| 主线清晰度 | 是否像一条可讲的职业故事 |
| 可信度 | 量化、客户/场景、职责边界是否清楚 |
| 风险项 | 时间断层、过短经历、术语硬伤、夸大风险 |
| 改写建议 | 按段落：保留 / 压缩 / 重写 / 补量化 |

**评分原则（产品约束）**

- 必须给出**扣分理由**，禁止只给分数  
- 建议按「人事会怎么刷」写，不用业务黑话堆砌  
- 改写默认**不编造经历**；缺信息标「待用户补充」

### 5.2 业务关：面试模拟（过关工具）

**输入**

- 简历 + JD（继承任务）  
- 可选：用户指定要练的案例（如 SRM、法规库解耦）

**流程**

1. 1 分钟自我介绍（含匹配点）  
2. 深挖 1–2 个项目（追问链）  
3. 情景题 / 压力题（计划拆解、冲突、短板）  
4. 反问环节提示（用户问面试官什么）

**诊断维度（针对「表层化」）**

| 维度 | 表层表现 | 合格表现 |
|------|----------|----------|
| STAR 完整度 | 只有背景和职责 | Action/Result 具体 |
| 决策与取舍 | 只说「后来做成了」 | 选项、标准、谁拍板 |
| 个人贡献 | 「我们」过多 | 清楚「我做了什么」 |
| 复盘 | 无 | 若重来会怎么做 |
| JD 迁移 | 硬套旧经验 | 说清可迁移方法与边界 |

**输出**

- 本轮深度分 + 最弱 1–2 点  
- 针对最弱题的「补强口述稿」（60–90 秒）  
- 可收藏为案例库条目

### 5.3 谈薪关：与 HR 沟通辅助（过关工具）

**输入**

- 当前：月薪结构、年终、奖金、公积金基数、补贴  
- Offer：基本/岗位/绩效、年终口径、试用期、调薪、其他  
- 用户底线与目标年包  

**输出**

- 双方**真实年包区间**（保守 / 目标 / 乐观）  
- 结构风险点（基本过低、年终不保、流水压价等）  
- 优先谈的 3 个点 + 可放弃的点  
- 话术：说明「应收结构 vs 流水」、要证据时怎么递  

**原则**

- 不算「保证你谈到 X」；给**决策信息 + 表达模板**  
- 明确标注：年终/绩效系数未书面确认时，按区间展示，不按满额单点展示  

### 5.4 职场心理教练（产品主身份）

**定位**：主故事线步骤 5 的核心——AI 心理疏导；并可导向私人心理辅导预约。

**输入**

- 初次评测 / 近期问卷结果与 AI 分析摘要  
- 用户已确认的诉求（求职 / 晋升 / 沟通等）  
- 可选：关联求职任务、晋升节点、冲突对象角色  

**流程（建议固定骨架）**

1. **门禁问卷**：进入疏导前按跟踪策略完成问卷（如三分钟自评）  
2. **澄清**：事实 vs 自我评判  
3. **命名情绪与需求**  
4. **重构选项**与 24h 可执行动作 / 话术  
5. **分支**：找工作 → 三关子流程；晋升/沟通 → 对应服务  
6. **预约**：用户可发起私人心理辅导预约  
7. **安全检查**：危机信号 → 转介，不继续常规疏导  

**私人心理辅导预约（步骤 5 增强）**

| 项 | MVP 建议 |
|----|----------|
| 能力 | 用户提交预约意向（时段偏好、诉求摘要、联系方式约定） |
| 履约 | 人工确认或对接外部咨询师；产品内展示预约状态 |
| 边界 | AI 疏导 ≠ 临床治疗；预约是专业支持通道，不承诺诊疗效果 |

### 5.5 员工心理健康跟踪（状态层）

**定位**：主故事线步骤 8——持续跟踪；**每次**进入疏导或关键节点前需完成问卷调查，而不是仅靠随意打卡。

**问卷策略**

| 时机 | 问卷 |
|------|------|
| 首次进入（步骤 2） | [`初次心理评估问卷.md`](./初次心理评估问卷.md) + **AI 评估分析** |
| 每次疏导 / 关键跟踪节点（步骤 8） | [`三分钟自评表.md`](./三分钟自评表.md) 或等价短问卷（可配置） |
| 可选重测基线 | 初次评估问卷（如 ≥90 天或用户主动） |

**输出**

- 近 7 / 30 日压力与情绪趋势（由问卷分数与标签汇总）  
- 「高压日」与诉求/事件对照  
- 可供「我的评估」与教练上下文引用的历史记录  

**原则**

- 默认私密、仅本人可见  
- AI 分析只用描述性语言，**禁止诊断病名**  
- 连续高压或危机相关作答 → 提示专业资源 / 引导预约，而非加强产品内依赖

## 7. 关键用户流程

### 主流程：首访到可持续使用（§0.4）

1. **链接登录**进入应用  
2. **第一次心理评测** → 提交后 **AI 评估 + 分析**  
3. **询问具体诉求**，与第 2 步结合，确认建议路径  
4. 用户可在「我的评估」**回看**报告  
5. 进入 **AI 心理疏导**；需要时可 **预约私人心理辅导**  
6. 若找工作 → **人事 → 业务 → 谈薪** 子流程  
7. 若晋升 / 沟通 → **对应场景服务**  
8. 持续跟踪：每次疏导或关键节点前 **完成问卷**，写入心理健康曲线  

### 子流程 A：求职三关

1. 新建任务 → 上传简历 + 粘贴 JD  
2. 人事关 → 看分与红灯 → 改写  
3. 业务关 → 模拟与诊断  
4. 谈薪关 → 结构对照与话术  

### 子流程 B：晋升 / 沟通服务

1. 基于诉求与评测进入场景  
2. 教练疏导 + 可执行下一步  
3. （增强）述职/沟通专项训练  

### 子流程 C：私人辅导预约

1. 从疏导页或工作台发起预约  
2. 填写时段与备注 → 待确认  
3. 确认后履约；回访可再引导问卷跟踪

## 8. 技术选型

结合已有栈（Vue3 + Go + SQLite）与已拍板约束：

| 层 | 选型 | 理由 |
|----|------|------|
| 前端 | Vue 3 + Vite | 熟悉；工作台 SPA |
| 后端 | Go | 熟悉；上传与 API 清晰 |
| 存储 | JSON 文件（`data/tasks.json`） | M1 零 CGO、依赖少、易备份；后续可换 SQLite |
| 部署 | **可公网/局域网访问的 Web 服务**（非纯本机桌面工具） | 方便真实投递场景随时用；可用单机 Docker / 一台云主机 |
| AI | OpenAI 兼容协议，**服务端对接自有中转站** | Key 与 Base URL 仅服务端配置，不暴露给终端用户 |
| 文档解析 | **Markdown / 纯文本 / docx / PDF** 均需支持 | MVP 输入门槛对齐真实投递材料 |

### 模块划分

```
apps/web          # Vue3 工作台
apps/api          # Go HTTP API
  /auth/link              # 链接登录
  /assessments            # 初次评测与 AI 分析、我的评估
  /needs                  # 诉求确认
  /coach/sessions         # AI 心理疏导
  /counseling/bookings    # 私人心理辅导预约
  /wellbeing/questionnaires  # 跟踪问卷（含三分钟自评）
  /tasks /hr /interview /salary   # 求职三关
internal/llm      # 评测分析 + 教练 + 三关 prompt
internal/resume   # 简历解析
```

### AI 调用原则

- **评测分析** / **教练疏导** / 人事 / 业务 / 谈薪使用不同 prompt 与 schema  
- 评测分析与疏导均须：职场向、禁止临床诊断、危机识别与转介  
- 疏导上下文注入：最近问卷、AI 评估摘要、已确认诉求  
- 中转站配置仅服务端；心理健康数据单独强调隐私说明  

### 简历解析原则

| 格式 | MVP 要求 |
|------|----------|
| Markdown / 纯文本 | 直接入库与结构化 |
| docx | 抽正文与基本标题层级，再结构化 |
| PDF | 抽文本（优先可选中文本型 PDF；扫描件 OCR 标为降级/二期增强） |

解析失败时明确报错并允许用户改贴纯文本，不静默空跑。

## 9. MVP 范围与非目标

### MVP 做（主故事线必须可演示）

按 §0.4 八步主路径验收，而不是只验收三关。

- **链接登录**进入应用（受控访问即可）  
- **初次心理评测** + **AI 评估分析**报告  
- **诉求确认**（与评测结合）  
- **我的评估**可回看  
- **AI 心理疏导** + **私人心理辅导预约**入口与状态  
- **求职子流程**：人事 → 业务 → 谈薪可跑通  
- **晋升 / 沟通**：至少以场景化疏导服务可用（专用训练可增强）  
- **心理健康跟踪**：每次疏导/关键节点前需完成问卷，并形成可回看曲线  
- 中转站 + SQLite；简历 md/txt/docx/pdf  

### MVP 不做

- 自动投递 / 爬岗位 / 替代 Boss 直聘  
- 完整多租户 SaaS 计费与开放自助注册（链接/白名单受控即可）  
- 终端用户自填模型 Key  
- 临床诊断、药物建议、危机陪护  
- 企业管理者查看员工心理数据的组织端监控  
- 扫描件 PDF 高精 OCR；英文面试专线  

说明：原「不做真人咨询师撮合」调整为——**支持私人心理辅导预约通道**（人工确认/外部对接），仍不在产品内开展诊疗。

## 11. 已拍板决策

| # | 问题 | 决策 |
|---|------|------|
| 1 | 部署形态 | **可访问的 Web 服务**；用户经**链接登录**进入 |
| 2 | 模型 Key | **先接自有中转站**；暂不开放用户自填 |
| 3 | 主路径 | **§0.4 八步主故事线**；求职三关与晋升/沟通为分支 |
| 4 | 简历格式 | **Markdown、纯文本、docx、PDF** 在求职子流程中需支持 |
| 5 | 产品定位 | **职场心理教练**；评测 + AI 分析 + 疏导 + 跟踪为骨干 |
| 6 | 心理边界 | 职场向、非临床诊断；危机转介；数据仅本人可见 |
| 7 | 真人辅导 | **支持私人心理辅导预约**（通道/状态）；不在站内做诊疗 |
| 8 | 跟踪方式 | **每次**疏导或关键节点前需问卷调查（非纯自愿打卡） |

待定细则：链接鉴权具体形态、预约对接咨询师还是人工排期、晋升/沟通专用训练的深度、对外品牌名。

## 12. 一句话路线

用户经**链接登录**，先做**心理评测并由 AI 评估分析**，再确认诉求；可回看结果，用 **AI 疏导**并预约**私人辅导**；找工作则走人事→业务→谈薪，晋升/沟通走对应服务；全程用**问卷跟踪**心理健康——产品是职场心理教练，不是改简历工具箱。
