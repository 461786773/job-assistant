# 求职助手 · 产品方案 v1

> 定位：**职场心理教练**——陪伴有履历的职场人（尤其跨赛道/跨岗位迁移的 ToB 产品人）在求职、晋升、沟通等高压节点里，稳住状态、理清选择、练好表达  
> 教练怎么帮：用**觉察与跟踪**稳住心理，用**场景辅导**理清情绪与下一步，用**过关工具**（人事筛简历 → 业务面深度 → HR 谈薪）把「下一句怎么说」练到可执行  
> 首发人群：**3–10 年经验**的社招 / 在职迁移者；垂类优先 **车联网 / 网络安全 / 合规（含信息安全→数据安全迁移）**  
> 明确不做：应届生、纯小白、零基础转行；**不是临床心理诊疗 / 危机干预替代品**；也不是又一个泛 AI 改简历工具

---

## 0. 核心策略（专项调整）

### 0.1 策略一句话

产品首先是**职场心理教练**，不是「招聘三关工具箱再挂个心理彩蛋」。用户来找的是：有人帮我在关键节点稳住、想清、说得出；简历/面试/谈薪是教练场景下的**训练与过关手段**。

### 0.2 教练模型（主从关系）

| 层 | 角色 | 解决什么 | 典型产出 |
|----|------|----------|----------|
| **教练主线** | 职场心理教练 | 求职 / 晋升 / 沟通中的压力、自我怀疑、冲突耗竭；帮用户拆开事实与评判，选定下一步 | 辅导对话、行动卡、「下一句怎么说」 |
| **状态层** | 心理健康跟踪 | 把零散情绪变成可回看曲线，与关键事件挂钩，供教练会话引用 | 打卡、趋势、周复盘摘要 |
| **过关工具层** | 三关训练 | 简历 / 面试 / 谈薪「过不过、差在哪、怎么改/怎么答」 | 报告、模拟记录、谈薪对照与话术 |

关系：**教练主线统领** → 跟踪提供上下文 → 三关工具在需要时被教练调用或由用户主动进入，而不是反过来用工具定义产品。

### 0.3 原则与边界

- **教练身份优先**：默认入口与叙事是「教练陪你过这个节点」，不是「先建一个投递任务」。  
- **职场向、非诊疗**：支持觉察、表达整理、压力缓冲与行动建议；**不诊断、不开药、不替代持证心理咨询/精神科**。  
- **高风险兜底**：出现自伤/伤人等危机信号时，明确提示寻求专业/紧急帮助，产品不继续「陪聊式处理危机」。  
- **绑在真实节点上**：辅导与跟踪挂在求职任务、晋升述职、冲突会等具体事件上，避免泛泛心灵鸡汤。  
- **隐私优先**：心理健康数据默认仅本人可见；存储与导出需单独说明。

## 1. 问题与目标

### 1.1 真实痛点（来自首要用户典型经历）

| 关卡 / 场景 | 痛点 | 失败/卡点形态 |
|------|------|----------------|
| 人事 | 简历主线不清、缺量化、与 JD 不对齐；跨赛道时「像不像这个岗」说不清 | 电话不错但不约面；简历保护期卡住多岗投递 |
| 业务 | 经历会背，但取舍/计划拆解/冲突处理讲不透；相邻岗位（如信息安全→数据合规）迁移叙事弱 | 「讲述表层化」「偏既定计划执行」；一面过二面挂 |
| 谈薪 | 不懂结构、被流水压价、不知哪些点可谈；主机厂/大厂 offer 拆分复杂 | 总包预期与 offer 结构错位；应收 vs 实发说不清 |
| 求职心理 | 长期投递耗竭、挂面后自我否定、在职偷投的焦虑与羞耻感 | 能力其实够，但状态崩导致发挥失常或直接放弃 |
| 晋升心理 | 述职前 rumination、怕暴露短板、与上级预期错位带来的持续紧张 | 「会干活不会呈现」；晋升窗口错过或谈崩 |
| 沟通心理 | 跨部门冲突、向上管理、被否定后情绪劫持 | 会后反复内耗；该争取的没争取、该止损的没止损 |

### 1.2 产品目标

- **不是**泛 AI 改简历 / 泛陪聊，也**不是**通用心理健康 App 或临床咨询替代  
- **而是**一个**职场心理教练**：在求职、晋升、沟通等节点上，帮用户稳住状态、理清选择、练好表达  
- 三关（人事 / 业务 / 谈薪）是教练场景下的**过关训练工具**，服务于「这个节点我怎么过」，而不是产品的唯一身份  

### 1.3 成功标准（MVP）

首要用户在真实高压节点上，能体验到「教练感」并带走：

1. 至少一次挂在具体场景（求职 / 晋升 / 沟通）上的**教练对话** + 可执行调节动作 / 话术  
2. 一段可回看的**心理健康跟踪**（情绪/压力打卡 + 与事件关联）  

并在需要过关训练时，能带走：

3. 一份「人事视角」打分报告 + 可落地的改写清单  
4. 一轮「业务视角」模拟面记录 + 表层化诊断  
5. 一份谈薪对照表 + 避坑问题 / 话术草稿

## 2. 目标用户（必须说清：服务谁、不服务谁）

### 2.1 一句话 ICP（理想客户）

**3–10 年经验、做过 ToB 平台/安全/运维类产品、正在换东家或争取晋升，既需要人帮他把状态稳住、把选择理清，也需要在关键节点把简历/面试/谈薪练到位的人。**

首发只做这类**有履历的社招 / 在职迁移与晋升**；不做应届生、不做纯小白；产品身份是**职场心理教练**（非临床诊疗）。

### 2.2 首要用户画像（Primary）

| 维度 | 定义 |
|------|------|
| 身份 | 产品经理为主；也包含「产品+项目」双角色、或从安全工具/平台侧转主机厂合规岗的人 |
| 经验 | **3–10 年**；至少有一段可被业务深挖的完整项目/客户交付（不是校招、不是纯小白） |
| 背景赛道 | 云原生 / 安全运营 / 运维安全 / 车联网 CSMS·TARA·VSOC 等，至少一段可讲清的平台或合规落地 |
| 当前求职动作 | 在职或刚离职的**主动社招**；已有完整简历，频繁按不同 JD 改主线、模拟面试、谈薪；或在职准备**晋升述职** |
| 目标去向 | 主机厂、车企软件侧、安全厂商、合规相关岗位；常见迁移包括：信息安全合规 → 数据合规、工具型产品 → 更贴整车/业务的合规或系统岗 |
| 能力特征 | 有真实项目与客户（如主机厂落地），但不擅长：把经历写成人事爱看的主线、把案例讲到业务认可的深度、把 offer 结构谈清楚；高压节点易自我否定或沟通耗竭 |
| 核心动机 | 不是「再找一个改简历网站」，而是「有个职场教练陪我过这个节点——状态别崩、话能说清、关能过」 |
| 付费/使用触发 | 约面前后 48 小时、改简历卡壳、二面挂掉复盘、HR 约谈薪当周；晋升述职前一周；重大冲突会后当晚；连续高压想有人帮看着状态 |

**典型一天（场景锚点）**

> 面完情绪低落，先打开教练：把「自我否定」和「可改进点」拆开，定一个今晚能做的动作。若还要推 JD，再进人事关改主线；若明天有业务面，用模拟把「计划怎么拆」练深。状态打卡把压力峰值标在「二面 / 晋升沟通 / 冲突会」等事件上，方便下周回看触发点。

### 2.3 为什么是这群人（针对性，而非泛产品经理）

1. **迁移叙事难**：履历跨云、安全、车联网，人事看「杂」，业务看「够不够深」——通用改简历工具解决不了「对这个 JD 该强调哪条线」。  
2. **过关标准特殊**：业务面常考法规拆解、阀点/里程碑、跨部门冲突、供应商/系统对接取舍；需要 STAR + 反表层化，而不是互联网 C 端产品那套「增长/用户故事」话术。  
3. **谈薪结构复杂**：主机厂/大厂常见基本+岗位+绩效+年终系数+公积金口径；「流水压价 vs 应收总包」是高频痛点。  
4. **高压长周期**：社招迁移 / 晋升往往持续数周到数月，能力问题与心理耗竭缠在一起——只做技能辅导不够，只做泛泛倾诉也不够。  
5. **我们有可验证的黄金用例**：产品规则与 prompt 可先用这一垂类的真实失败/成功路径打磨，再扩邻域。

### 2.4 应届生 / 纯小白：不做进 MVP

决策已定：**MVP 只面对 3–10 年有履历的社招求职者**；应届生、纯小白、零基础转行不适合本切口（缺可深挖交付，三关会退化成模板与八股，也与创始人可验证路径不一致）。校招若未来要做，另立项，不挤进当前默认任务流。

### 2.5 明确不服务（首发 Out of scope）

| 非目标用户（首发） | 原因 |
|--------------------|------|
| 应届生、纯小白、零基础转行 | 见 2.4；MVP 明确不做 |
| 经验不足 3 年且几乎无可深挖项目 | 业务关「反表层化」缺少原料 |
| 纯技术岗求职（开发/测试刷题为主） | 过关逻辑是题库与编码，不是三关叙事 |
| 纯职能 HR/行政/销售话术训练 | 面试模型不同 |
| 想「一键海投 / 自动改到能骗过 ATS」的用户 | 与「不编造经历、可验证深度」原则冲突 |
| 需要临床心理治疗 / 精神疾病诊疗的用户 | 产品边界是职场支持，须引导专业服务 |
| 把产品当 24h 危机热线的用户 | 危机场景仅做识别与转介提示，不做持续危机陪护 |

### 2.6 次要用户（可服务，但不为他们定 MVP）

- 同一垂类里偏 **售前 / 解决方案**，需要按 JD 调简历与案例深度的人  
- 安全厂商 PM，主线更稳、主要需要谈薪与压力面（人事关权重可降低）  
- 二期同框架扩展：通用 ToB 平台 PM、其他强合规行业（须另做行业题库）  

### 2.7 用户分层与产品对应

| 层级 | 是谁 | 产品必须提供的 |
|------|------|----------------|
| P0 首要 | **3–10 年**、车联网/网安/合规方向、跨岗或跨雇主迁移中的产品人 | **职场心理教练**主路径（求职/晋升/沟通）+ 轻量跟踪；需要时调用 JD 主线改写、反表层化模拟、薪酬对照 |
| P1 扩展 | 同垂类售前/方案、安全厂商 PM；在职晋升述职者 | 同一教练框架；晋升/沟通权重更高；题库与关键词包可配置 |
| P2 远期 | 更广 ToB 社招 PM（仍建议 3 年+有履历） | 抽「职场高压节点教练」共性，减弱垂类绑死文案 |
| 不做 | 应届 / 纯小白；临床诊疗需求 | 不在本产品 MVP 范围 |

### 2.8 核心场景

**主路径 A：职场心理教练（产品默认叙事）**

```
选择场景（求职 / 晋升 / 沟通）+ 可选关联任务或事件
    → 状态打卡（情绪 / 压力轻量指标）
    → 教练对话（澄清事实 vs 自我评判、可执行调节与下一句怎么说）
    → 写入心理健康跟踪（与事件挂钩，可回看趋势）
    → 若节点需要过关训练 → 跳转人事 / 业务 / 谈薪工具
```

**主路径 B：求职过关训练（教练场景下的工具）**

```
上传简历 + 粘贴 JD（明确目标岗：如数据合规 / CSMS 产品）
    → 人事评分与「按该 JD 的主线」改写建议
    → 进入业务模拟（追问迁移边界、计划拆解、冲突取舍）
    → 按 STAR + 反表层化诊断回答深度
    → 拿到 offer 结构后进入谈薪辅助（流水 vs 应收、年终口径）
    → 关键节点可随时回到教练会话（挂面、谈薪前焦虑等）
```

次要场景（后期）：多 JD 主线对比、挂面复盘、个人 STAR 案例库沉淀、晋升述职稿与教练联动。

## 5. 能力设计

> 结构：**5.4 职场心理教练**与 **5.5 心理健康跟踪**是产品主身份与状态层；**5.1–5.3 三关**是教练场景下可调用的过关训练工具。

### 5.1 人事关：简历评分与改写（过关工具）

**输入**

- 简历全文（结构化优先：工作经历 / 项目 / 优势）  
- 目标 JD  
- 可选：求职意向主线（如「车联网合规产品」）

**输出**

| 维度 | 说明 |
|------|------|
| 匹配度 | 与 JD 关键词 / 职责的覆盖 |
| 主线清晰度 | 是否像一条可讲的职业故事 |
| 可信度 | 量化、客户/场景、职责边界是否清楚 |
| 风险项 | 时间断层、过短经历、术语硬伤、夸大风险 |
| 改写建议 | 按段落：保留 / 压缩 / 重写 / 补量化 |

**评分原则（产品约束）**

- 必须给出**扣分理由**，禁止只给分数  
- 建议按「人事会怎么刷」写，不用业务黑话堆砌  
- 改写默认**不编造经历**；缺信息标「待用户补充」

### 5.2 业务关：面试模拟（过关工具）

**输入**

- 简历 + JD（继承任务）  
- 可选：用户指定要练的案例（如 SRM、法规库解耦）

**流程**

1. 1 分钟自我介绍（含匹配点）  
2. 深挖 1–2 个项目（追问链）  
3. 情景题 / 压力题（计划拆解、冲突、短板）  
4. 反问环节提示（用户问面试官什么）

**诊断维度（针对「表层化」）**

| 维度 | 表层表现 | 合格表现 |
|------|----------|----------|
| STAR 完整度 | 只有背景和职责 | Action/Result 具体 |
| 决策与取舍 | 只说「后来做成了」 | 选项、标准、谁拍板 |
| 个人贡献 | 「我们」过多 | 清楚「我做了什么」 |
| 复盘 | 无 | 若重来会怎么做 |
| JD 迁移 | 硬套旧经验 | 说清可迁移方法与边界 |

**输出**

- 本轮深度分 + 最弱 1–2 点  
- 针对最弱题的「补强口述稿」（60–90 秒）  
- 可收藏为案例库条目

### 5.3 谈薪关：与 HR 沟通辅助（过关工具）

**输入**

- 当前：月薪结构、年终、奖金、公积金基数、补贴  
- Offer：基本/岗位/绩效、年终口径、试用期、调薪、其他  
- 用户底线与目标年包  

**输出**

- 双方**真实年包区间**（保守 / 目标 / 乐观）  
- 结构风险点（基本过低、年终不保、流水压价等）  
- 优先谈的 3 个点 + 可放弃的点  
- 话术：说明「应收结构 vs 流水」、要证据时怎么递  

**原则**

- 不算「保证你谈到 X」；给**决策信息 + 表达模板**  
- 明确标注：年终/绩效系数未书面确认时，按区间展示，不按满额单点展示  

### 5.4 职场心理教练（产品主身份）

**定位**：产品的默认身份——职场心理教练。在求职、晋升、沟通等高频节点上，帮用户把「情绪」与「可行动事实」分开，给出下一小步；需要时再调用三关训练工具。

**输入**

- 场景标签：`job_search` | `promotion` | `communication`（可扩展）  
- 可选：关联求职任务 ID、晋升节点备注、冲突对象角色（上级/平级/跨部门）  
- 可选：当日打卡数据（压力分、情绪标签）  

**流程（建议固定骨架，避免无边界陪聊）**

1. **澄清**：发生了什么（事实）vs 我告诉自己的故事（评判）  
2. **命名情绪与需求**：焦虑 / 羞耻 / 愤怒 / 耗竭等 + 真正需要什么（确认、边界、休息、准备）  
3. **重构选项**：1–3 个可执行选项（含「暂不行动」）  
4. **落地输出**：一个 24 小时内可做的动作 +（如适用）「下一句怎么说」话术草稿  
5. **需要过关时**：引导进入人事 / 业务 / 谈薪训练，而不是在教练会话里硬改简历全文  
6. **安全检查**：若检测到危机信号 → 中断常规教练，展示专业求助资源  

**场景要点**

| 场景 | 教练重点 | 典型输出 |
|------|----------|----------|
| 求职 | 挂面后自我否定、投递耗竭、在职偷投焦虑 | 事实/评判拆分；复盘清单；是否继续投该 JD 的决策框；可跳转三关训练 |
| 晋升 | 述职前 rumination、怕暴露短板、与上级预期错位 | 述职叙事压力点；向上沟通要点；自我价值与职级标准对齐 |
| 沟通 | 冲突会后情绪劫持、该争取/该止损 | 边界与诉求澄清；会后跟进话术；冷却策略 |

**原则**

- 共情后必须落到**可验证的下一步**，禁止纯鸡汤收尾  
- 不替用户做重大人生决定（离职/接受 offer/撕破脸），只帮澄清标准与选项  
- 教练 prompt 与输出 schema **独立于**人事/业务/谈薪三角色；三关是被调用的工具，不是教练本身  

### 5.5 员工心理健康跟踪（状态层）

**定位**：轻量、可坚持的自我跟踪，让用户看见「状态—事件」关联，而不是医学诊断量表替代品。

**打卡字段（MVP 建议极简）**

| 字段 | 说明 |
|------|------|
| 日期 / 时刻 | 自动 |
| 压力分 | 1–5 或 1–10 |
| 情绪标签 | 多选：平静 / 焦虑 / 低落 / 烦躁 / 兴奋 等 |
| 精力（可选） | 1–5 |
| 关联事件 | 面试、挂面、谈薪、晋升述职、冲突会、无事件 等 |
| 一句话备注 | 可选，短文本 |

**输出**

- 近 7 / 30 日压力趋势与情绪分布  
- 「高压日」与关键事件对照（如挂面当日压力峰值）  
- 简短复盘摘要（可每周生成一次）：本周触发点 + 曾奏效的调节动作  

**原则**

- 默认私密、仅本人可见  
- 不做临床诊断结论（禁止输出「你有抑郁症」类表述）  
- 连续高压或危机相关打卡 → 提示专业资源，而非加强产品内依赖  

初次进入教练前，使用基线问卷定场景与状态起点，详见 [`初次心理评估问卷.md`](./初次心理评估问卷.md)。会话开场或节点快评可用 [`三分钟自评表.md`](./三分钟自评表.md)。

## 7. 关键用户流程

### 流程 A：准备投递

1. 新建任务 → 上传简历 + 粘贴 JD  
2. 跑人事关 → 看分与红灯 → 按建议改简历（站内或导出）  
3. 认为过关后，标记「可投递」

### 流程 B：约面后刷题

1. 进入同一任务的业务关  
2. 选「完整模拟」或「只练薄弱点」  
3. 结束后看诊断，把补强稿练到能口述  

### 流程 C：拿到口头/书面 offer

1. 填结构字段  
2. 看总包对照与风险  
3. 复制话术去聊；回来可更新「对方答复」再迭代策略  

### 流程 D：职场心理教练（默认主路径）

1. 选场景 → 可选关联任务或事件 → 可选先打卡  
2. 进入教练对话（澄清 → 命名 → 选项 → 行动）  
3. 带走 1 个 24h 动作 / 话术；需要过关时跳转三关训练  
4. 会话写入跟踪时间线  

### 流程 E：心理健康跟踪

1. 日常或关键节点后轻量打卡  
2. 在趋势页回看高压日与事件对照  
3. 可选生成周复盘摘要，并跳转一次针对性辅导

## 8. 技术选型

结合已有栈（Vue3 + Go + SQLite）与已拍板约束：

| 层 | 选型 | 理由 |
|----|------|------|
| 前端 | Vue 3 + Vite | 熟悉；工作台 SPA |
| 后端 | Go | 熟悉；上传与 API 清晰 |
| 存储 | JSON 文件（`data/tasks.json`） | M1 零 CGO、依赖少、易备份；后续可换 SQLite |
| 部署 | **可公网/局域网访问的 Web 服务**（非纯本机桌面工具） | 方便真实投递场景随时用；可用单机 Docker / 一台云主机 |
| AI | OpenAI 兼容协议，**服务端对接自有中转站** | Key 与 Base URL 仅服务端配置，不暴露给终端用户 |
| 文档解析 | **Markdown / 纯文本 / docx / PDF** 均需支持 | MVP 输入门槛对齐真实投递材料 |

### 模块划分

```
apps/web          # Vue3 工作台（浏览器访问）
apps/api          # Go HTTP API
  /tasks
  /hr/analyze
  /interview/sessions
  /salary/analyze
  /coach/sessions     # 职场心理教练（主身份）
  /wellbeing/checkins # 心理健康打卡与趋势
internal/llm      # 中转站 client + 多角色 prompt（教练 + 三关工具）
internal/resume   # md / txt / docx / pdf 解析与结构化
```

### AI 调用原则

- **教练** / 人事 / 业务 / 谈薪使用**不同 system prompt 与输出 schema**（角色隔离）；教练为默认叙事角色  
- 业务模拟要带「反表层化」评分细则  
- 教练 prompt 必须包含：职场教练身份、禁止临床诊断、危机识别与转介话术、何时建议跳转三关工具  
- 中转站：`base_url` + `api_key` + `model` 写在服务端环境变量 / 配置文件，**首发不提供「用户自填 Key」入口**（二期可加）  
- 用户简历、JD 与心理健康数据存于自建服务；产品需有隐私说明（心理健康数据单独强调）  

### 简历解析原则

| 格式 | MVP 要求 |
|------|----------|
| Markdown / 纯文本 | 直接入库与结构化 |
| docx | 抽正文与基本标题层级，再结构化 |
| PDF | 抽文本（优先可选中文本型 PDF；扫描件 OCR 标为降级/二期增强） |

解析失败时明确报错并允许用户改贴纯文本，不静默空跑。

## 9. MVP 范围与非目标

### MVP 做（教练主线 + 过关工具最小闭环）

首发原则：用户打开产品，首先感到这是**职场心理教练**；求职三关作为可调用的过关训练，须能整条跑通，但**不再用「只有三关」定义产品身份**。

**教练主线**

- 可访问的 Web 服务；默认首页为**教练工作台**  
- 职场心理教练：覆盖 **求职 / 晋升 / 沟通** 三场景；会话输出含行动项与（可选）话术  
- 心理健康跟踪：轻量打卡 + 近 7/30 日趋势 + 与事件关联  
- 危机识别：固定文案转介，不提供危机陪护流程  
- 隐私说明：设置页标明心理健康数据用途与可见范围  
- 服务端对接自有 LLM 中转站；SQLite 持久化  

**过关工具层**

- 任务创建：上传 **md / txt / docx / pdf** + 粘贴 JD  
- ① 人事关：评分报告 + 改写建议（可选生成改写稿）  
- ② 业务关：模拟对话（介绍 + 3–5 追问 + 总结诊断，含反表层化）  
- ③ 谈薪关：结构表单 + 年包对照 + 避坑问题 / 话术  
- 关键节点可从任务回到教练会话  

### MVP 不做

- 自动投递 / 爬岗位 / 替代 Boss 直聘的岗位流量  
- 多租户 SaaS 计费、用户自助注册体系（首发可以是受控访问：账号白名单或简单登录）  
- 终端用户自填模型 Key（首发仅运营方中转站）  
- 真人面试官撮合 / 真人心理咨询师撮合  
- 临床心理测评量表、诊断结论、药物建议  
- 企业 HR/管理者查看员工心理健康数据的「组织端监控」（首发仅员工本人）  
- 扫描件 PDF 的高精 OCR（文本型 PDF 必须支持）  
- 英文面试专线（可作二期开关）

## 10. 里程碑

| 阶段 | 交付 | 验收 |
|------|------|------|
| M0 方案 | 本文档对齐 | 定位确认为**职场心理教练**；人群与边界确认 |
| M1 骨架 | Vue + Go；可部署 Web；教练工作台壳 + 任务 CRUD；四格式上传解析 | 浏览器打开默认进教练工作台；简历可进任务 |
| M2 教练最小闭环 | 三场景教练会话 + 打卡/趋势 + 危机文案 | 挂面/晋升/沟通节点能完成一次教练并留下跟踪点 |
| M3 人事关 | 中转站接入 + 分析 API + 报告页 | 真实简历+JD → 分项分与改写清单 |
| M4 业务关 | 模拟会话 + 反表层化诊断 | 能打出「表层化」类反馈与补强稿 |
| M5 谈薪关 | 结构计算 + 话术 | 流水/结构对照 + 避坑问题 |
| M6 主线验收 | 教练主线 + 三关工具串联打磨 + 部署文档 | **一次真实高压节点走完教练；需要时跑通三关训练** |

M3–M5 可与 M2 并行界面开发。**M6 以「教练感成立 + 过关工具可用」为发布门槛**。

## 11. 已拍板决策

| # | 问题 | 决策 |
|---|------|------|
| 1 | 部署形态 | **可访问的 Web 服务**（非纯本机单用户工具） |
| 2 | 模型 Key | **先接自有中转站**（服务端配置）；暂不开放用户自填 |
| 3 | 过关工具 | **三关训练须一起跑通**；不做「仅人事关」半成品；但三关是工具层，不是产品主身份 |
| 4 | 简历格式 | **Markdown、纯文本、docx、PDF** MVP 均需支持 |
| 5 | 产品定位 | **职场心理教练**（主身份）；心理健康跟踪为状态层；招聘三关为过关工具层 |
| 6 | 心理边界 | **职场向教练，非临床诊疗**；危机只做识别与转介；首发数据仅本人可见 |

待实现时再定的细则（不阻塞开工）：中转站 Base URL / 模型名、域名与 HTTPS、是否加简单登录口令；教练所用具体轻量量表口径；危机资源文案清单；产品对外品牌名是否仍用「求职助手」。

## 12. 一句话路线

做面向 **3–10 年 ToB/安全/合规人群** 的**职场心理教练**：在求职、晋升、沟通节点稳住状态、理清选择、练好表达，并用可访问 Web + 自有中转站提供心理健康跟踪与人事/业务/谈薪过关训练；输入兼容 md/docx/pdf，先用自己的真实高压节点与求职材料当黄金验收集。
